# Kel Portfolio Studio 使用说明

这是连接现有网站项目的 Windows 便携编辑器。双击 `Kel-Portfolio-Studio-1.0.0.exe` 即可启动，不需要安装。请保留 `E:\Kel-MyselfWeb\my-portfolio` 项目目录及其中已安装的网站依赖。应用不把网站项目复制进自身，也不需要每次手动启动网站。

## 日常使用

1. 打开应用。默认连接上述项目目录，以**预览模式**启动。
2. 点击顶部**切换到编辑**，使用原有网页里的编辑入口。编辑后先点页面自身的保存按钮。
3. 点击**切换到预览**，检查访客视图。切换时会重新载入当前页面；尚未保存的表单内容不会保留。
4. 点击顶部**一键上传**，填写版本名，例如 `1.2.0 · 更新游戏规划`。
5. 检查变更文件清单，点击**构建、提交并上传**。应用先构建网站，再以 `release: 版本名` 创建 Git 提交，推送到现有 `origin` 的当前分支。

应用只接受现有仓库 `KelAess111/MyWeb`，不会创建新仓库或切换分支。当前项目使用 `main` 分支。上传使用这台电脑已有的 Git 登录信息；若未登录或权限失效，需要恢复 Git 登录后重试。

“上传成功”表示 GitHub 收到提交。若现有 Vercel 项目已经关联这个仓库和分支，它会按原配置继续部署。应用不将 Git 上传成功表述为部署已完成，也不更改托管设置。

上传失败但提交已创建时，应用会保存 `.kel-release.local`。再次打开发布面板并点击上传，会重试原提交，不会重复创建版本。若手动切换分支或改变 HEAD，则需先自行处理这份重试记录。

## 编辑权限

- 普通网站远端和正式预览构建保持只读，添加 URL 参数、留下旧浏览器标记都不能启用编辑。
- 本地开发编辑需要开发环境、回环地址、启用本地编辑配置，以及明确进入编辑模式。预览参数优先于编辑参数。
- 本地文件保存接口仅出现在开发服务器，校验回环连接、Host、Origin 和编辑请求头。
- 桌面应用顶部的上传按钮只存在于 App，网站页面不显示上传入口。
- 构建时移除作者自动登录密码和本地编辑密钥；`.env`、`*.env`、`*.local`、密钥文件、其他工作区和构建产物不进入应用上传清单。
- 若项目已有暂存更改，应用会停止发布，请先处理这些更改。

## 内容保存在哪里

**游戏规划**保存到 `public/content/game-plans.json`，随 Git 发布成为远端网站的公开内容。保存时保留本地备份。若有更早只存在浏览器里的规划，请在原浏览器的本地编辑页面使用“导入此浏览器的旧规划”；App 有独立的浏览器数据，无法读取 Edge 原有的浏览器存储。

**Anki 新增和修改的词库**保存到 `public/content/anki-cards.json`，随网站一起发布。原 Supabase 词库仍会读取并合并；重复的词自动跳过，云端暂时不可用时仍可载入精选词。修改旧云端卡片时采用本地文件覆盖，删除采用文件内的删除标记，不删除原云端数据。

**已有文章、日记等云端模块**沿用原来的 Supabase 保存方式。本次统一了它们的本地编辑权限，但没有迁移这些模块的存储；保存这些内容可能立即更新云端，不能把 App 的预览／编辑切换理解为全站的离线草稿系统。

**Anki 学习记录、弃置和新错题**保存在当前浏览器中，不再通过“弃置”修改作者的共享词库。早期已登录账号的云端练习历史和错题仍可读取。App 使用独立的固定本地地址，学习记录与浏览器网页端互相独立；不会自动跨设备同步。

## 词库与批量导入

已附带英语六级方向 120 词、日语 N2 方向 122 词，包含中文释义、词性、读音和原创用法提示。日语同时保留假名和汉字。精选词包含中级学习所需的基础与进阶词，不是完整考试词表或官方等级保证。

JLPT 官方不发布固定的各级词汇清单，参见 [JLPT FAQ](https://www.jlpt.jp/e/faq/index.html)。这些卡片按学习方向自行选词、编写释义与提示。

在本地编辑模式进入“词库管理”，展开“批量导入 / 精选词库”：

1. 可预览精选包，用于补回被移除的精选词。
2. 也可从表格粘贴，每行一张卡片，6 列依次为：**原文、读音、汉字、词性、中文释义、注释**，用 Tab 分隔。
3. 没有内容的列留空，原文和释义必填。每次最多 2000 行。
4. 点击“检查并预览”，再点“导入并自动去重”。重复项按照同语言下的原文、汉字及规范化形式识别，不覆盖已有卡片。
5. 保存并发布后，远端站点会获得新增词库。网站原有的学习登录要求保持不变。

## 维护与检查

- App 的源代码在项目 `desktop/` 中。应用包没有代码签名。
- 从源代码运行：先执行 `npm run desktop:install`，再在 `desktop` 内执行 `npm run install:runtime`，然后执行 `npm run desktop:dev`。
- 网站检查：`npm run test:editor`；正式构建：`npm run build`。
- App 重打包：`npm run desktop:build`。默认产物在 `desktop/dist/`。
- 如果 App 提示本地端口已被占用，请先关闭另一个 Studio 或占用 `127.0.0.1:5186` 的进程。不会自动结束其他 Node 进程。

## 已修复的口令明文

最终检查发现，旧版隐藏房间入口的明文口令与本地作者登录密码相同。新版入口改为带随机盐的 PBKDF2 校验，并验证原入口操作仍可使用；新公开构建中已检测不到该明文。以后的构建也会自动检查作者密码和编辑密钥，发现泄漏就中止。

旧源码和 Git 历史可能仍保留原值，因此建议你自行更换作者登录密码，并避免与隐藏入口口令复用。隐藏房间原有的前端入口本身不等于服务端私密内容授权；原有云端权限规则仍负责保护数据。
更换作者登录密码后，请同步更新本机 `.env.local` 中的 `VITE_AUTHOR_PASSWORD`，以便原有云端模块继续在本地自动登录。

## 写作区作者登录修复

本地编辑写作区时会使用 .env.local 中已有的作者账号自动连接 Supabase，无需先发布网站。App 与 Edge 的登录存储相互独立；写作和日记现在共用本地作者登录流程。网络或登录失败时保留本地改动并给出具体提示，后续可再次保存以同步。此次只修改项目源文件，关闭后重开原 App 即可加载。
